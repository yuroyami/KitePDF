# FABLE audit: what each lane read and found sound

Companion to FABLE_AUDIT.md. Each lane listed the areas it read closely without finding a defect, so the owner knows what the audit covered and what it did not.

## XCUT
- kitepdf-net `fetch`: streams the body through `prepareGet` and `execute`, checks Content-Length before reading, caps bytes with an overflow-safe comparison, redacts user info and query from URLs in messages, rethrows CancellationException. Timeouts are the client's by documented design.
- `KnockoutCanvas` (kitepdf-pdf/render) overrides both `drawImage` overloads and both `applySoftMask` overloads despite `by inner` delegation, so the gotcha of #290 does not recur there. `SvgPlacements` in EpubDocument delegates to `NoopCanvas` and only collects, so the defaults are harmless.
- `KiteBitmapCache`: first retained result wins, no callback under the lock, generation token prevents repopulation after `clear`, budget arithmetic guards Long.MAX_VALUE.
- `ByteArrayBuilder`: growth doubles with an Int.MAX_VALUE guard and a clear exception past the array limit.
- `readPosixFile` (three byte-identical copies by design): `fopen "rb"`, `ftell` sign check, 2 GB guard, short-read check, `fclose` in finally.
- PdfDocument caches (decoded images, operations, fonts): LRU with budgets, trims under the lock, parse and decode outside the lock, first writer wins, `drop*` hooks public.
- `PdfDocument.pageCount` trusts `/Count` only when it is at most the xref size and defers building a large page list off the first frame (#387); `pageCountIn` gives the exact count.
- The KiteJS JVM probe classes (`AsmCodeHistogram`, `AsmProfileProbe`, `AsmRealModuleProbe`) are opt-in through `assumeTrue` on environment variables by design; note that the JVM runner's class-name filter also skips them, so the documented `KITEJS_PROFILE=true` run needs `--include-classes='*Probe*'` to reach them (a one-line doc fix in KiteJS).
- KiteJS builds the Android JNI libraries with `-Wl,-z,max-page-size=16384` (build-plugins/quickjs-android/src/androidTasks.kt:52), so the 16 KB page requirement of Android 15 is met.
- kitepdf-javascript documents the web `prepare()` requirement (docs/javascript.md:228) that wraps KiteJS's `QuickJs.load()`.
- No `runBlocking`, `Dispatchers.IO`, `synchronized` or `java.*` use in any common `src/` of the published modules (only in kitepdf-difftest, a JVM test helper, and in JVM/native source sets).
- The writer builds every dictionary it serialises from `LinkedHashMap`, so output byte order is deterministic on every platform.

## VIEWER-API
- `KiteZoomSpec`, `Continuous`, `Paged`, `Spread`, `Rasterized`, `Vectorized` and `KiteScrollPosition` `init` checks for sign and NaN as far as they go; `KiteZoomSpec(maxZoom = 4f, doubleTapZoom = 10f)` clamps as documented.
- `setZoom`, `animateZoomTo`, `panBy` and the focal point ignore NaN and infinite input (`ViewerInputLimitsSceneTest`); `rasterPlanFor` guards a non-finite zoom and a sub-pixel side.
- `SinglePage` with an index outside the document, a negative index, a book still laying out, an empty chapter: nearest page, warning logged, placeholder until placeable, navigation off (`SinglePageIndexSceneTest`); `canNavigate` makes internal links fall through to `onTap` as documented.
- `Spread` with a reflowable EPUB waits for `stripSettled` and shows the chapter placeholder, as the KDoc says; `pageOverlay` is composed in every layout including `Spread` through `PageSlotContent`.
- Switching `layout` or `renderSpec` at run time: the old adapter parks the position and clears itself only if it is still current; a `Continuous` orientation switch converts the offset (`PositionOwnershipSceneTest`); a `Rasterized` to `Vectorized` switch drops the bitmap cache (#395); the vector image cache is dropped on dispose and on a budget change; `key(state)` gives a new state new containers.
- `selectionEnabled = false` removes the long press and the mouse selection and clears a selection already on screen; `kiteSelectionGestures` returns the bare modifier.
- `prefetchPages` with a tiny `maxBitmapLongSide` draws the capped bitmap under the key the slot asks for, and `imageCacheBudgetBytes = 0` disables retention as documented.
- `KiteDocViewColors.theme` overrides the paper everywhere (page, placeholder, chapter gap, thumbnails), and the cache key is the paper colour, so a hidden background change does not re-raster (#394, `CacheKeyTest`).
- `KiteExternalLinks` allow-lists schemes in lower case and `externalLinks = null` opens nothing; `onLinkTap` sees every link first in every format; the deprecated `(PdfAction) -> Boolean` callback gets only links the viewer cannot follow (`LinkTapSceneTest.the_old_link_callback_only_gets_the_links_the_viewer_cannot_follow`).
- `Deprecated.kt`: every alias resolves to the new type; every quick fix passes each argument by name and drops none, and the three functions whose `onLinkTap` changed type have no quick fix (`DeprecatedReplacementsTest`, `DeprecatedAliasTest`). `PdfView`, `EpubView`, `rememberPdfViewState`, `rememberEpubViewState` forward argument for argument.
- `KiteRenderSpec.Vectorized` keeps its two-argument constructor and `copy` beside the three-argument data class ones; `KitePageHit` and `KiteTextSelection` keep their old constructors and a `copy` that preserves `location`; the klib and JVM dumps agree with the source.
- Java and Swift: nothing in the README or docs claims the viewer is callable from Java or Swift (a `@Composable` cannot be), and the state's constructors export cleanly; `KiteDocViewState(document)` needs the `initialPage` argument from Java (no `@JvmOverloads`), which no document promises otherwise.
- `KiteDocViewState.saver` round-trips a flow bookmark and a scroll position and clamps negative values; `rememberKiteDocViewState` keys on the document only, so a new document is a new state and a restored position wins over the `initialPage` or bookmark argument, which is the standard Compose contract.
- The documents have no `close()`, so "a state reused after close" has no code path; a page whose content is dropped by the layout budget acts as a page without text or links until it is back (`DroppedChapterSceneTest`).
- Accessibility labels: pages, chevrons, thumbnails, selection colours, the external-link prompt (pane title, Escape and Enter), the hidden form input (tooltip or name) and choice controls are named and translatable through `LocalKiteViewerStrings`; `KiteSelectionMenu` chips merge their label through `clickable(role = Button)`.
- I found no viewer test in this lane that cannot fail: `ContinuousPrefetchSceneTest` asserts the gap of VIEWER-API-05 on purpose, and the scene driver throws when a wait runs out.

## VIEWER-RUNTIME
- `RasterGate`: permits released in `finally`; a waiter cancelled before the hand-off leaves the queue; one cancelled after it passes the slot on through the `resume` cancellation lambda; priority is read at release time, so a page that scrolls into view moves ahead; no path holds a permit while waiting for the UI thread on JVM, Android or Apple (`textOffMain` is true there); `RasterGateTest` covers these six properties.
- `PageBitmapCache`: keyed on page identity, size, paper, theme by value, hairline bits, widget skipping, decorator identity, text measurer, tile region and content version; the byte estimate saturates; eviction is LRU under one lock; the whole instance is swapped when the budget changes and an in-flight raster writes to the old instance harmlessly, as documented.
- `GlyphMaskCache`: identity keys are valid because every outline source caches its paths (Type1Font.kt:45-59, TrueTypeFont.kt:41, CffFont.kt:82-119, `standardFaceOutline` through `glyphSpaceCache`), and the host outlines of `PageRenderer.hostOutlined` go to clips, strokes and pattern fills, never to `drawGlyphs`, so they cannot thrash it; masks are built outside the lock; the budget bounds the coverage.
- `KiteBitmapCache`: generation token prevents a cleared cache from being repopulated by a late conversion; no callback runs under the lock.
- `PdfDocument` caches: the decoded image, operation and font caches trim under the document lock with LRU order, first writer wins on a race, and an item larger than its budget is handed back without being kept; `pages` is a synchronized lazy, so page identity is stable for the viewer's keys. There is no `close()` on any document, so there is no use after close; a swapped document's rasters stop between operators once their slots leave composition.
- `EpubDocument` chapter state: `prepareChapter` checks readiness before taking the per-chapter lock, so a UI-thread `page()` of a ready chapter never waits behind a layout; the budget keeps `kept` chapters and one chapter always; loader chapters get `lastUse = 0` so the reader's chapter is dropped last; page objects are permanent per (chapter, page) across drops, so the viewer's identity keys and `hostFontLandings` stay bounded by the page count.
- `ComposeCanvas` on a pool thread: Skia paints, paths, layers, gradients and colour filters; Android `Bitmap`, `Path`, `Paint`, `TextPaint` and `RadialGradient`; the per-thread `HostShaping` on JVM and Apple; `hostFontFamily`'s unsynchronised `cjkFamilies` is reached only through Compose's text, which the canvas uses on the web and in tests only; the Vectorized canvas runs inside the scene's draw pass with a locked shared image cache.
- `KiteDocView` effects: adapters park and detach on dispose, geometry entries are removed per slot, `keepChapters(emptySet())` and the vector cache clear run on dispose, `attachViewerThread` clears itself, `runPageScripts` closes the open page from a scope of its own on purpose, the timer pumps clear their wake channel, and `KiteFormRevision` stops its listener.
- Thread hops: every `snapshotFlow` collector and every state write after a `withContext` or `delay` calls `backOnComposeThread()`; `onComposeThread` uses the frame clock; `EffectThreadSceneTest` covers the eight shapes.
- Script lanes: `Dispatchers.IO.limitedParallelism(1)` views own no threads, so a viewer leaks none; `PdfScriptRunner` owns one thread per runner, which is the host's object to close.
- Media: a player is closed in `DisposableEffect(open)` and unregistered from the session; an open that fails drops the player, which the same effect closes; `KiteMediaSession` is called on the main thread only, as documented; `BackgroundHandling` closes the platform session; full screen on Android and iOS restores orientation on dispose.
- Apple: the viewer's actuals call Skia only off the main thread (`FontMgr.default`, paragraphs, bitmaps), `NSThread.currentThread` is an equality-stable marker, and the one UIKit call (`requestGeometryUpdateWithPreferences`) runs in a `DisposableEffect` on the main thread.
- Web: chapter layout is sliced by `prepareInSlices` and held back by `awaitRest`, rasters run in one pass on purpose (#389), one gate permit serialises them, and a waiting raster is removed from the queue when its slot leaves, so a fling wastes at most the one raster that holds the permit.
- No `runBlocking` in the viewer or media sources; no lock is held across a suspension point.

## PDF-PARSE
- Cycle/recursion guards: `withCycleClaim` (per-thread owner set + `resolutionDepth`), page-tree walk (`visited` + `MAX_PAGE_TREE_DEPTH` 50), `/Prev` chain (`visited` + `MAX_PREV_HOPS` 32, `/XRefStm` added to visited), name/number tree walkers (`MAX_DEPTH` 64), outline (`MAX_DEPTH`/`MAX_SIBLINGS`), structure tree (`MAX_ELEMENTS`/`MAX_DEPTH`/`visited`), form-field parent walks (`MAX_PARENT_DEPTH`) are all bounded; no superlinear or unbounded recursion found there.
- Stream `/Length`: indirect/self-referential `/Length` is handled (resolver cycle claim + `runCatching` in `resolveStreamLengthOrNull`, endstream-scan fallback); wrong/missing `/Length` falls back to a bounded `endstream` scan.
- R6 hash (Algorithm 2.B): the loop bound (`round < 64 || lastByte > round - 32`), the "sum of first 16 bytes of E mod 3" shortcut (correct because 256 congruent 1 mod 3), and the SHA-256/384/512 selection match the spec and MuPDF; owner-password-only and empty-user-password V5 paths authenticate correctly; `/EncryptMetadata false` key extension (4x 0xFF) and the `Decryptor` Metadata/XRef skips are correct.
- ZipReader: bounds are thorough (`hasRange`/`checkedEnd` everywhere, ZIP64 EOCD + locator + per-entry extra field, data-descriptor resolution for streamed entries, `uncompressedSize`/CRC cross-checks, multi-disk and trailing-record rejection, `maxEntryBytes`/`maxEntries` caps). No integer-overflow or OOB indexing found; `readPrefix` and the stored/streamed descriptor scans are bounded.
- KiteXml entity expansion: bounded by `MAX_EXPANSION_DEPTH` (16) and a shared `EXPANSION_BUDGET` (1,000,000 chars), external entities expand to empty, `referenceEnd` is bounded by `HtmlEntities.LONGEST`; the billion-laughs class is closed. `KiteXml.parse` fold is O(n) via `openPositions`.
- Inline-image length math (`ContentStreamParser.unfilteredDataLength`) is carefully overflow-checked in `Long` with per-step guards; the EI scan is boundary-aware with a raw fallback and a forced-progress loop, so content parsing cannot stall.
- `formatOf` detectors are ordered defensively (ZIP before PDF-in-text, EPUB mimetype at fixed offset with central-directory fallback, XPS requires a real fixed-document-sequence root before the CBZ image heuristic, SVG checked last); a PDF embedding `<svg` text is not misclassified, and the strict CBZ "all real entries are images" rule avoids photo-backup false positives.
- `kitepdf-net` caps the body before and during download (`Content-Length` pre-check plus running `maxBytes` guard over `prepareGet { }.execute { }` streaming), honours `CancellationException`, and scrubs credentials from diagnostic URLs.
- AES CBC/ECB, RC4, MD5/SHA-256/384/512 table constants and the V1-V4 per-object key derivation (object/gen little-endian + `sAlT` for AESV2, MD5, `min(n+5,16)` truncation) read correctly; `stripPkcs7` is defensive; empty/short AES ciphertext returns empty rather than throwing.

## PDF-RENDER
- Text state arithmetic: `Tz` scales `Tc`, `Tw` and `TJ` adjustments through `textToUser` and `totalAdvance`; `Ts` is applied in text space before `Tm` so it follows a rotated line; `TD` sets `TL = -ty`; `T*`, `'` and `"` move by `-TL`; `TJ` in vertical mode moves down without `Tz`; Type 3 advances use `wx * FontMatrix.a * Tfs + Tc (+ Tw for byte 32)`.
- Pattern space: `patternBaseCtm` is the page's base CTM, the form's CTM after its `/Matrix` for forms and annotation appearances, the tile CTM inside a cell and the glyph CTM inside a Type 3 glyph (8.7.3.1); the fill region stays under the paint-time CTM and only the shading follows the pattern matrix.
- Annotations: Algorithm 8.1 (BBox corners through `/Matrix`, upright box, map to `/Rect`), NoZoom anchoring, `/CA` applied once through a group, Hidden and NoView flags, Popup skipped, `/OC` on annotations, `/AS` state selection with the `/Off` then first fallback, one failing annotation skipped.
- Optional content: `/D` with `/BaseState`, `/ON`, `/OFF`, `/AS` View usage with AND over categories; OCMD `/VE` with depth cap and `/P` AllOn, AnyOff, AllOff, AnyOn; nested `/OC` on image and form XObjects; marked-content hiding with floors per nested stream.
- Graphics state stack: `q`/`Q` paired with the canvas clip stack through `clipSaveStack`, floors per nested stream so a form's extra `Q` cannot pop its caller, `W`/`W*` applied after the painting operator and reset at stream boundaries, clip depth and marked-content depth caps, `GraphicsStack` overflow pairing.
- Soft masks: mask CTM frozen at `gs` (11.6.5.2), `/BC` converted in the group's `/CS`, `/TR` sampled to 256 levels with the backdrop level mapped too, luminosity over opaque black, a group's own soft mask reset to None inside a transparency group (11.6.6), the group alpha taken from `ca` once.
- Blend modes: `RasterBlend` implements the twelve separable and four non-separable formulas of 11.3.5 on premultiplied colour with the correct `(1 - ab) Cs + (1 - as) Cb + as ab B` compositing; all six canvases map all sixteen modes; knockout handled with Src, Copy or destination-out plus a layer per nested group.
- Strokes: the miter test `1 / cos(half angle) <= miterLimit` equals the spec's `1 / sin(phi / 2)` (8.4.3.5); dash phase wraps modulo the pattern, each dash gets caps, a zero-length dash under round caps is a dot and under square caps a square along the direction; a zero-length subpath paints a dot with round caps and nothing otherwise (8.5.3.2); the hairline floor and the one-fifth-pixel thin-line floor are shared by every canvas through `strokePen`; the elliptical pen under a non-uniform CTM is drawn in user space.
- Functions: Type 0 samples read big-endian with the first input varying fastest, `Encode` default `[0 Size-1]`, `Decode` default `Range`, multilinear interpolation with clamped indices; Type 2 `C0`/`C1` defaults; Type 3 half-open subdomains with the last closed; Type 4 `atan` in degrees in 0..360, `cvi` and `truncate` toward zero, `round` ties up, `idiv`/`mod` on integers, `roll` direction, `index`, `copy`, bitwise `and`/`or`/`xor`/`not` on integers and logical on booleans, underflow tolerated, non-finite outputs zeroed.
- Colour: Lab `f(t)` threshold and `/Range` clamp with `Decode` defaults of 0..100 and the declared ranges (Table 90), CalGray gamma, CalRGB gamma and column-major matrix with Bradford adaptation to D65, ICC matrix/TRC and parametric curve types 0 to 4, ICC LUT selection per intent with black point compensation, `/Alternate` used only when the profile does not apply and `/N` the last resort (8.6.5.5), Separation `/None` painting nothing, Indexed palette scaled by the base's own component ranges.
- Meshes: type 4 records padded to bytes, flag 1 and 2 edge reuse, type 6 and 7 boundary order and shared-edge tables (Table 85), Coons interior points by the 8.7.4.5.7 formula, tensor interior order, bilinear corner colours, a 256-entry colour table for meshes with a `/Function`, MuPDF's triangle fill rule.
- Images: `/Decode` for stencils (`[1 0]` inverts), stencil `/Mask` sense, colour-key comparison on source samples before `Decode` (8.9.6.4), `/Matte` unblending, 16-bit samples by the high byte in masks and full width in `readBits`, `/SMaskInData` honoured when the JPX carries alpha, CMYK JPEG samples kept as stored with the Adobe transform marker taking precedence over `/ColorTransform` and `/Decode` left to the file, `/Interpolate` through one shared sampling policy, grid fitting as MuPDF, JBIG2 globals by filter position.
- Caches and locking: `PdfDocument` font, image, operation and object caches under one `KiteLock`; `KiteBitmapCache` locked with build outside the lock; `IccProfile.parse` cache locked; `AwtCanvas.hostOutlines` a `ConcurrentHashMap`; per-canvas glyph caches not shared.
- The text collector canvas (`StructuredText.kt`) receives invisible, outlined and clipping text through `drawGlyphs` and ignores pixels, with ink boxes cut by clips.

## PDF-WRITE
- `PdfObjectWriter`: reals never carry an exponent, `-0.0` and NaN/Infinity become `0`, 6 decimals with trailing zeros trimmed, Long magnitudes past 1e12 fall back to integer form; literal strings escape `(`, `)` and `\` and anything outside 0x20..0x7E goes hex; names escape delimiters, `#` and space; `/Length` is always the direct byte count; no `String.format`, no locale-dependent call, no charset conversion of binary data anywhere in the writer.
- Header `%PDF-1.7` plus a four-byte binary comment; `startxref` offsets computed from the builder size; incremental sections start on a fresh line when the base does not end with an EOL; xref entries are exactly 20 bytes with `0000000000 65535 f` first; `/Prev` is the base's own `startxref`; `/Root`, `/Info`, `/Encrypt` and `/ID` are carried; a hybrid base's `/XRefStm` is reached through the `/Prev` chain by every reader that reads the old trailer.
- A classic table appended over a cross-reference-stream base (what `saveIncremental` always writes) is read correctly by PDFium 5.14, pdf.js 4.10 and pypdf (probe `probe_xrefstream_incremental.py`: the updated object wins in all three), so the style mismatch with MuPDF's writer is cosmetic. mutool itself could not be run here.
- The repaired-base save (#586 class) lists every in-use object at the offset repair found, rewrites compressed objects as top-level ones (re-encrypted, `/Encrypt` excepted) and names no `/Prev`.
- Generation numbers: `updateObject` keeps the reference's generation in the object header, the xref entry and the AESV2 object key; new numbers never reuse a free entry (they start above both the highest xref key and `/Size - 1`).
- `saveRewritten`: dense renumbering from 1, dangling references become `null`, the `/Encrypt` dictionary and the linearization dictionary and hint streams are unreachable and dropped, stream objects stay out of the object stream, the xref stream's `/W` widths fit the largest field, `/Index [0 Size]`.
- Encryption on write: V5 uses the file key directly with no object salt, V4 AESV2 derives the key per object from number, generation and `sAlT` (Algorithm 1); each string and stream gets a 16-byte IV from the caller's `Random`; `Random.Default` is never used (the DSL has no default for `random`, and `edit()` without one refuses an encrypted document); `/XRef` streams and, when `/EncryptMetadata false`, `/Metadata` streams stay clear; the `/Encrypt` dictionary itself is never encrypted; new `/Info` strings of an incremental save are encrypted; Algorithms 8, 9, 10 (including the `/Perms` block layout) and the 2.B hardening loop match ISO 32000-2, and the output opens in pypdf, pdf.js and PDFium with the user and the owner password.
- Redaction removes text by position regardless of render mode (invisible OCR text in mode 3 goes), replaces removed runs with a `TJ` advance so later text keeps its place, handles `TJ` arrays, vertical fonts and Type 3 widths, drops inline images and `sh` by clip, prunes dropped XObjects from `/Resources`, refuses `saveIncremental` after a redaction, removes annotations whose `/Rect` meets a region and scrubs their text, appearance, actions and file specs, and detaches their fields from `/Fields` and `/CO`.
- Text-field values with quotes, parentheses or backslashes are escaped in both `/V` and the appearance stream; `/NeedAppearances` is cleared; rich text keeps `/RV` in step.
- `PdfSigner`: `/ByteRange` covers the whole file except the hex string, the placeholder is patched at a fixed width, `embedSignature` keeps zero padding, encrypted documents are refused; `/SigFlags 3`.
- `FontEmbedder`: `/CIDToGIDMap` stream keyed by original glyph id (the code the content stream emits), `/W` runs, `/DW 1000`, `ToUnicode` in blocks of at most 100 `bfchar` with surrogate pairs, `/FontFile2` with `/Length1` for TrueType and `/FontFile3 /CIDFontType0C` for CFF, a deterministic subset tag.

## EPUB-LAYOUT
- `Deobfuscate`: the IDPF key is SHA-1 of the unique identifier with the four XML white space characters removed, XOR over the first 1040 bytes with a 20-byte cycle; the Adobe key is the 16 bytes of the UUID hex after the last colon over 1024 bytes; `Sha1` pads and encodes the length as RFC 3174 says. `parseEncryption` keys by the resolved `CipherReference` URI and the identifier falls back to the first `dc:identifier` when `unique-identifier` names nothing.
- `Brotli`: window bits, the fixed tables, the simple and complex prefix codes with completeness checks, the context maps with inverse MTF, the distance ring buffer and short codes, the dictionary transforms with the UTF-8 fermenting, the meta-block length checks and the output cap; every loop consumes input or output, so a truncated or hostile stream throws rather than spinning.
